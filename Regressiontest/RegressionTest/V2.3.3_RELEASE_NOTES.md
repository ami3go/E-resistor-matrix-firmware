# E-Resistor Regression Test v2.3.3

## Packaging contract

- The outer archive filename may include a product description and version.
- The archive contains one fixed internal root folder: `RegressionTest/`.
- Runtime artifacts such as `.venv/`, `results/`, `__pycache__/`, and local bench configuration are not included in the release archive.

## Windows environment and BAT launchers

- Every pure-Python and Robot Framework BAT launcher now validates the local `.venv` before execution.
- Missing, moved, damaged, or unsupported virtual environments are removed and recreated automatically.
- A missing `pip` installation is repaired with `ensurepip`.
- Required Python, HIL, and Robot Framework dependencies are checked and installed when absent or inconsistent.
- Setup error handling no longer relies on stale `%errorlevel%` expansion inside parenthesized CMD blocks.
- Setup diagnostics are written to `results/setup/last_setup_diagnostics.txt`.
- The example source directory is empty by default, so normal regression runs do not accidentally use a placeholder firmware path.

## Diagnostic evidence

- Each run receives a unique run ID included in structured log context.
- `diagnostics.json` and `diagnostics.md` record Python, package, platform, and network information.
- HIL runs additionally inventory detected COM ports and VISA resources without opening active-output paths.
- `RUN_INCOMPLETE` is created at run start and removed only after successful evidence finalization.
- Test exceptions include the exception representation and Python traceback in detailed evidence.
- Failed automatic VISA probes now close every temporary instrument handle.

## HIL safety coverage

- Active HIL masks are verified immediately after application.
- The same eight-channel state is verified again after DMM settling and measurement.
- The selected channel must retain the requested mask while all other seven channels remain `0000`.
- Final cleanup retries `ALL:OFF` and verifies `STATE?` for all eight channels.
- `SAFE-999` records verified final cleanup as an explicit PASS or FAIL result for pure-Python and Robot Framework runs.
- Cleanup verification failure changes the overall regression status to FAIL.

## Validation still required on the target bench

The release build environment is Linux and has no Windows `cmd.exe`, Ethernet-connected E-Resistor, RP2040 COM/CDC device, or USB/VISA DMM. Therefore these checks must be executed on the real Windows HIL bench before declaring the release fully hardware-validated:

1. Run `setup_python_environment.bat` from a clean directory.
2. Delete `pip` from a test `.venv` and confirm automatic `ensurepip` repair.
3. Move or copy the package with an existing `.venv` and confirm automatic recreation.
4. Run all pure-Python BAT profiles.
5. Run all Robot Framework BAT profiles.
6. Confirm COM transcript capture and fault-pattern detection.
7. Confirm DMM auto-selection and explicit-resource selection.
8. Confirm all seven unselected channels remain `0000` throughout every physical measurement.
9. Disconnect Ethernet during cleanup and verify `SAFE-999` fails with useful retry evidence.
